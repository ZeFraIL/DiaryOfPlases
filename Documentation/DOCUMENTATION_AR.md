## 🎯 هدف المشروع
*   **ما المشكلة التي يحلها التطبيق:** يوفر وسيلة مريحة لتوثيق وتنظيم الأماكن التي تمت زيارتها مع الصور والملاحظات وإحداثيات GPS.
*   **لماذا هذه المهمة مهمة:** تساعد المستخدمين على الحفاظ على ذكريات رحلاتهم والعثور بسهولة على المواقع الهامة في المستقبل.
*   **الجمهور المستهدف:** المسافرون والمستكشفون والأشخاص الذين يرغبون في الاحتفاظ بسجل شخصي للأماكن.
________________________________________
## 📌 متطلبات التطبيق
### المتطلبات الوظيفية
*   إنشاء وعرض وتحرير وحذف إدخالات الأماكن.
*   إرفاق صور من الكاميرا للمواقع.
*   حفظ إحداثيات GPS للأماكن.
*   البحث عن المواقع.
*   أزرار اتصال الطوارئ (الشرطة، الإسعاف، الإطفاء).
*   المساعدة الصوتية (Text-to-Speech) لسهولة الوصول.
*   إدارة جهات الاتصال الشخصية.

### المتطلبات غير الوظيفية
*   **الأداء:** استرجاع سريع للبيانات من قاعدة بيانات SQLite المحلية.
*   **سهولة الاستخدام:** تنقل بسيط وواجهة مزودة بإرشادات صوتية.
*   **الموثوقية:** تخزين محلي دائم يضمن عدم فقدان البيانات عند إعادة تشغيل التطبيق.
________________________________________
## 🧠 العمارة العامة
*   **النهج المختار:**  
    MVC (Model-View-Controller)
*   **لماذا تم اختيار هذا النهج:**  
    إنه مناسب تمامًا للتطبيقات القائمة على الأنشطة (Activity) حيث تعمل الـ Activity كمنظم وعارض في نفس الوقت، مع التفاعل مع طبقة بيانات بسيطة (SQLite).
*   **مكونات النظام الرئيسية:**  
    *   **العارض/المنظم:** الأنشطة (`Start`, `MainChoise`, `AddPlace`, `ViewPlaces`).
    *   **طبقة البيانات:** `HelperDB` (SQLiteOpenHelper).
    *   **النموذج:** `Place`, `myContact`.
    *   **الأدوات المساعدة:** `TtsManager` للمساعدة الصوتية.
________________________________________
## 🧩 مخطط UML (وصف)
**سير العمل:**  
`[Start]` –> `[MainChoise]`  
`[MainChoise]` –> `[AddPlace]` / `[ViewPlaces]` / `[Search]` / `[Emergency]` / `[Guide]`  
`[ViewPlaces]` –> `[PlaceAdapter]` –> `[Place]`  
`[HelperDB]` <–> `[Place]` / `[myContact]`  

**التوسع:**  
يستخدم المشروع نشاطًا أساسيًا (`BaseActivity`) لمشاركة المنطق (القوائم، TTS)، مما يسهل التوسع عن طريق إضافة ميزات جديدة دون تكرار كود boilerplate.
________________________________________
## 🧩 وصف تفصيلي للفئات
### 📌 الفئة: Start
*   **الدور:** نقطة الدخول.
*   **المسؤولية:** تهيئة التطبيق وتوجيه المستخدم إلى القائمة الرئيسية أو المصادقة.
*   **الأساليب الرئيسية:**
    *   `onCreate()` — يقوم بإعداد واجهة المستخدم الأولية ومنطق التنقل.
*   **التفاعل:** يستدعي `LogOrReg` أو `MainChoise`.

### 📌 الفئة: BaseActivity
*   **الدور:** الفئة الأساسية لجميع الأنشطة.
*   **المسؤولية:** التعامل مع عناصر القائمة المشتركة (رجوع، خروج، الاعتمادات) وتهيئة `TtsManager`.
*   **الأساليب الرئيسية:**
    *   `speak(String message)` — يوفر المساعدة الصوتية إذا كانت مفعلة.

### 📌 الفئة: HelperDB (طبقة البيانات)
*   **الدور:** مدير قاعدة البيانات.
*   **المسؤولية:** إنشاء وترقية قاعدة بيانات SQLite، وتوفير أساليب لعمليات CRUD.

## 🔄 سيناريو عمل التطبيق
1.  **التشغيل:** يبدأ المستخدم التطبيق عبر `Start`.
2.  **التنقل:** يختار المستخدم إضافة مكان في `MainChoise`.
3.  **إدخال البيانات:** في `AddPlace` يقوم المستخدم بملء التفاصيل والتقاط صورة والحفظ.
4.  **التخزين:** يقوم `HelperDB` بحفظ كائن `Place` في قاعدة بيانات SQLite.
5.  **العرض:** ينتقل المستخدم إلى `ViewPlaces` لرؤية قائمة المواقع المحفوظة.

*   **لماذا تم تصميم الواجهة بهذا الشكل:** التركيز على البساطة وسهولة الوصول. الأزرار الكبيرة والعلامات الواضحة تسهل الاستخدام أثناء التنقل.
*   **المبادئ المستخدمة:**
    *   **البساطة:** تخطيط مبسط للميزات الأساسية.
    *   **المنطق:** تنقل هرمي يتبع أنماط أندروאיד القياسية.
    *   **سهولة الوصول:** دمج خاصية تحويل النص إلى كلام لمساعدة المستخدمين الذين يعانون من ضعف البصر.
*   **التحسينات:** الانتقال إلى تصميم Material 3 وإضافة الوضع الليلي (Dark Mode).

*   **التقنيات المستخدمة:**
    *   UI Thread القياسي للتفاعلات.
    *   التعامل الضمني مع الخيوط للكاميرا وتحديثات الموقع عبر واجهات برمجة تطبيقات نظام أندرويد.
*   **لماذا تم اختيار هذا الأسلوب:** يبسط الكود مع الاعتماد على معالجة قوية على مستوى النظام للمهام المتخصصة.
*   **الوقاية:**
    *   **ANR:** تجنب المعالجة الثقيلة في الخيط الرئيسي.
    *   **تسرب الذاكرة:** استخدام إدارة دورة حياة صحيحة في الأنشطة.
