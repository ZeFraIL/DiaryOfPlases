## 🎯 Цель проекта
*   **Какую задачу решает приложение:** Предоставляет удобный способ документирования и организации посещенных мест с фотографиями, заметками и координатами GPS.
*   **Почему эта задача важна:** Это помогает пользователям сохранять воспоминания о своих путешествиях и легко находить важные локации в будущем.
*   **Целевая аудитория:** Путешественники, исследователи и люди, желающие вести личный журнал мест.
________________________________________
## 📌 Требования к приложению
### Функциональные требования
*   Создание, просмотр, редактирование и удаление записей о местах.
*   Прикрепление фотографий с камеры к локациям.
*   Сохранение GPS-координат мест.
*   Поиск локаций.
*   Кнопки экстренного вызова (Полиция, Скорая помощь, Пожарная служба).
*   Голосовой помощник (Text-to-Speech) для доступности.
*   Управление личными контактами.

### Нефункциональные требования
*   **Производительность:** Быстрое извлечение данных из локальной базы данных SQLite.
*   **Удобство использования:** Простая навигация и интерфейс с голосовыми подсказками.
*   **Надёжность:** Постоянное локальное хранилище, гарантирующее отсутствие потери данных при перезапуске приложения.

## 🧠 Общая архитектура
*   **Выбранный подход:**  
    MVC (Model-View-Controller)
*   **Почему выбран именно он:**  
    Он хорошо подходит для приложений на основе Activity, где Activity выступает одновременно как контроллер и представление, взаимодействуя с простым слоем данных (SQLite).
*   **Основные компоненты системы:**  
    *   **Представление/Контроллер:** Активности (`Start`, `MainChoise`, `AddPlace`, `ViewPlaces`).
    *   **Слой данных:** `HelperDB` (SQLiteOpenHelper).
    *   **Модель:** `Place`, `myContact`.
    *   **Утилиты:** `TtsManager` для голосовой помощи.

## 🧩 UML-диаграмма (Описание)
**Рабочий процесс:**  
`[Start]` –> `[MainChoise]`  
`[MainChoise]` –> `[AddPlace]` / `[ViewPlaces]` / `[Search]` / `[Emergency]` / `[Guide]`  
`[ViewPlaces]` –> `[PlaceAdapter]` –> `[Place]`  
`[HelperDB]` <–> `[Place]` / `[myContact]`  

**Масштабирование:**  
Проект использует базовую активность (`BaseActivity`) для общего использования логики (меню, TTS), что облегчает масштабирование за счет добавления новых функций без дублирования шаблонного кода.

## 🧩 Подробное описание классов
### 📌 Класс: Start
*   **Роль:** Точка входа.
*   **Ответственность:** Инициализация приложения и переход пользователя к главному меню или аутентификации.
*   **Основные методы:**
    *   `onCreate()` — Настраивает начальный пользовательский интерфейс и логику навигации.
*   **Взаимодействие:** Вызывает `LogOrReg` или `MainChoise`.

### 📌 Класс: BaseActivity
*   **Роль:** Базовый класс для всех активностей.
*   **Ответственность:** Обработка общих пунктов меню (Назад, Выход, Титры) и инициализация `TtsManager`.
*   **Основные методы:**
    *   `speak(String message)` — Обеспечивает голосовую помощь, если она включена.

### 📌 Класс: HelperDB (Слой данных)
*   **Роль:** Менеджер базы данных.
*   **Ответственность:** Создание и обновление базы данных SQLite, предоставление методов для операций CRUD.
________________________________________
## 🔄 Сценарий работы приложения
1.  **Запуск:** Пользователь запускает приложение через `Start`.
2.  **Навигация:** Пользователь выбирает добавление места в `MainChoise`.
3.  **Ввод данных:** В `AddPlace` пользователь заполняет детали, делает фото и сохраняет.
4.  **Хранение:** `HelperDB` сохраняет объект `Place` в базу данных SQLite.
5.  **Просмотр:** Пользователь переходит в `ViewPlaces`, чтобы увидеть список сохраненных локаций.

## 🎨 UI/UX анализ
*   **Почему интерфейс сделан именно так:** Фокус на простоте и доступности. Крупные кнопки и четкие надписи облегчают использование на ходу.
*   **Какие принципы использованы:**
    *   **Простота:** Минималистичный макет для основных функций.
    *   **Логичность:** Иерархическая навигация в соответствии со стандартными паттернами Android.
    *   **Доступность:** Интегрированный Text-to-Speech для помощи пользователям с нарушениями зрения.
*   **Что можно улучшить:** Переход на дизайн Material 3 и добавление темной темы.
________________________________________
## ⚙️ Работа с потоками
*   **Используемые технологии:**
    *   Стандартный UI Thread для взаимодействий.
    *   Неявная обработка потоков для камеры и обновлений местоположения через API системы Android.
*   **Почему выбран этот способ:** Упрощает кодовую базу, полагаясь на надежную системную обработку специализированных задач.
*   **Как предотвращаются:**
    *   **ANR:** Избежание тяжелой обработки в основном потоке.
    *   **Утечки памяти:** Использование правильного управления жизненным циклом в активностях.
________________________________________
## 💾 Работа с данными
*   **Где хранятся данные:** Локальная база данных SQLite (`info.db`).
*   **Почему выбран этот способ:** Надежно, не требует интернет-соединения и эффективно обрабатывает структурированные данные.
*   **Как обеспечивается:**
    *   **Сохранность:** Атомарные операции SQLite.
    *   **Корректность:** Определенные схемы для мест и контактов.
________________________________________
## 🌐 Работа с сетью
*   **Использование:** Используется в `Search.java` для выполнения внешних запросов (через WebView/Intents).
*   **Обработка ошибок:** Проверка доступности интернета с помощью `InternetConnectorReceiver`.
