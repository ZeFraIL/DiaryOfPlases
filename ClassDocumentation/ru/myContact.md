# Описание класса: myContact

________________________________________
## 1. Общая информация
*   **Имя класса:** `myContact`
*   **Тип:** Модель / Класс данных (реализует `Serializable`)
*   **Назначение:** Этот класс представляет собой описание одного человека в приватном списке контактов пользователя. Он хранит имя, номер телефона, электронную почту и любые заметки о человеке.
*   **Взаимодействие:** Используется экраном `InnerContacts` для отображения списка людей и экраном `AddInnerContact` для создания или изменения их данных. Информация из этого класса сохраняется в базу данных через `HelperDB`.

________________________________________
## 2. Переменные (поля класса)
| Имя | Тип | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| `contactID` | `String` | Уникальный идентификатор контакта. | Для удаления или обновления конкретных строк в базе данных. |
| `contactName` | `String` | Полное имя человека. | Отображается в списках и диалогах. |
| `contactPhone`| `String` | Номер телефона. | Используется для звонков или отправки SMS. |
| `contactEmail`| `String` | Адрес электронной почты. | Используется для отправки писем. |
| `contactComment`| `String` | Дополнительные заметки о человеке. | Показывается в детальном просмотре. |

*   **Serializable:** Позволяет передавать весь объект контакта целиком как «посылку» между разными экранами приложения.

________________________________________
## 3. Методы класса

### Имя метода: `myContact` (Конструктор)
*   **Тип:** `public`
*   **Логика:** Когда мы создаем новый контакт в коде, этот метод берет все данные (ID, имя и т.д.) и сохраняет их в переменные созданного объекта.

### Методы `get...` / `set...` (Геттеры и Сеттеры)
*   **Тип:** `public`
*   **Логика:** Эти методы позволяют другим частям приложения читать данные контакта (`get`) или изменять их (`set`). Например, `getContactPhone()` возвращает номер телефона.

### Имя метода: `toString`
*   **Тип:** `public`
*   **Возвращаемое значение:** `String` (строка текста)
*   **Логика:** Собирает всю информацию о человеке в один текстовый блок, разделяя данные переносом строки.
*   **Когда вызывается:** Используется в `InnerContacts` для отображения данных во всплывающем окне или для озвучивания голосовым помощником.

________________________________________
## 4. Жизненный цикл
Это класс данных, поэтому у него нет жизненного цикла Android. Он существует в памяти телефона до тех пор, пока приложению нужна информация об этом конкретном человеке.

________________________________________
## 5. Взаимодействие с другими компонентами
*   **SQLite:** Поля класса соответствуют столбцам таблицы `TABLE_MY_CONTACT` в базе данных.
*   **AlertDialog:** Результат метода `toString()` часто используется как основной текст сообщения во всплывающих окнах.

________________________________________
## 6. Общая логика класса
Этот класс — это **чертеж** или **шаблон**. Он говорит приложению: «У каждого контакта обязательно должны быть эти пять полей данных». Он сам не звонит и не отправляет почту; он просто «держит» данные, которые нужны для этих действий.

________________________________________
## 7. Упрощенное объяснение
**Объяснение простыми словами:**
Представь, что класс `myContact` — это **физическая визитка**.
*   На визитке есть графы для **имени**, **телефона**, **почты** и **заметок**.
*   Объект `myContact` — это одна конкретная визитка с вписанными в неё данными.
*   Если ты хочешь узнать, как связаться с человеком, ты берешь его «визитку» и читаешь номер телефона.

**Аналогия:** Это как **запись в бумажной записной книжке**. Она просто лежит там и хранит информацию до тех пор, пока ты не решишь поднять трубку и набрать номер.
