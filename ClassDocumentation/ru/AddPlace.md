# Описание класса: AddPlace

________________________________________
## 1. Общая информация
*   **Имя класса:** `AddPlace`
*   **Тип:** Активность (Activity)
*   **Назначение:** Этот экран позволяет пользователю создать новую запись в своем «Дневнике мест». Он собирает название, комментарий, фотографию, ссылку на веб-сайт и GPS-координаты, а затем сохраняет их в локальную базу данных.
*   **Взаимодействие:** Наследуется от `BaseActivity` (получая его меню и голосового помощника). Взаимодействует с камерой, экраном поиска (`Search`), экраном местоположения (`MyLocation`) и базой данных (`HelperDB`).

________________________________________
## 2. Переменные (поля класса)
| Имя | Тип | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| `etName` | `EditText` | Поле ввода названия места. | Для получения текста и именования файла фото. |
| `etComment` | `EditText` | Поле ввода описания. | Для получения заметок пользователя. |
| `ivImage` | `ImageView` | Отображает фотографию, сделанную камерой. | Чтобы пользователь видел результат съемки. |
| `stGPS` | `String` | Хранит координаты, полученные из `MyLocation`. | Передается в объект `Place` для сохранения. |
| `stLink` | `String` | Хранит URL-ссылку, полученную из экрана поиска. | Передается в объект `Place` для сохранения. |
| `imageUri` | `Uri` | Внутренний путь, по которому будет сохранено фото. | Используется при запуске камеры. |

*   **Uri:** «Унифицированный идентификатор ресурса» — по сути, цифровой адрес файла в памяти телефона.
*   **ActivityResultLauncher:** Современный инструмент для запуска других экранов (Камера, Поиск) и ожидания результата от них (фотография, ссылка).

________________________________________
## 3. Методы класса

### Имя метода: `onCreate`
*   **Тип:** `protected`
*   **Логика:**
    1. Инициализирует элементы интерфейса.
    2. Запрашивает необходимые разрешения (Камера, Память).
    3. Устанавливает слушатели нажатий: для фото (запуск камеры), для кнопок ссылки (Поиск) и GPS (Локация), и для кнопки сохранения.
*   **Когда вызывается:** При переходе пользователя на экран добавления места.

### Имя метода: `createImageUri`
*   **Тип:** `private`
*   **Возвращаемое значение:** `Uri` (путь к созданному файлу)
*   **Логика:** Генерирует уникальное имя файла на основе названия места и текущей даты, создает временный файл в папке картинок телефона и возвращает его адрес.
*   **Что важно понимать:** Использует `FileProvider` для безопасной передачи пути к файлу приложению камеры.

### Имя метода: `confirmAndSavePlace`
*   **Тип:** `private`
*   **Логика:**
    1. Проверяет, что название, комментарий и фото не пусты.
    2. Показывает диалоговое окно подтверждения (`AlertDialog`).
    3. Если пользователь нажимает «Ок», запускает процесс сохранения в фоновом режиме.
*   **Когда вызывается:** При нажатии на кнопку «Save Place».

### Имя метода: `savePlaceInBackground`
*   **Тип:** `private`
*   **Логика:**
    1. Запускает фоновый поток (`ExecutorService`), чтобы интерфейс не завис.
    2. Превращает картинку из `ImageView` в набор байтов (сжимая в формат PNG).
    3. Создает объект `Place`.
    4. Использует `HelperDB` для записи данных в таблицу SQLite.
    5. Возвращается в основной поток (`Handler`), чтобы показать сообщение об успехе и закрыть экран.
*   **Зачем фоновый поток?** Обработка изображений и запись в базу — медленные операции. Если делать их в основном потоке, приложение может «заикаться» или выдать ошибку ANR (приложение не отвечает).

________________________________________
## 4. Жизненный цикл
*   **onCreate():** Настройка экрана и кнопок.
*   **onDestroy():** Наследуется от `BaseActivity`.

________________________________________
## 5. Взаимодействие с интерфейсом (UI)
*   **EditText:** Поля для ввода текста.
*   **ImageView:** Работает как кнопка для запуска камеры, а затем как контейнер для фото.
*   **Buttons:** `bLink` (Поиск), `bGPS` (Координаты), `bSavePlace` (Сохранение).

________________________________________
## 6. Взаимодействие с другими компонентами
*   **Intent:** Для перехода к `Search` и `MyLocation`.
*   **ActivityResultContracts:** Для получения данных обратно из этих экранов.
*   **SQLite:** Сохранение данных через `ContentValues` и `HelperDB`.

________________________________________
## 7. Общая логика класса
1. Пользователь вводит название места.
2. Пользователь нажимает на картинку, делает фото, и оно появляется на экране.
3. По желанию пользователь ищет ссылку в интернете или определяет координаты.
4. Пользователь нажимает «Сохранить».
5. Приложение проверяет данные, сжимает фото и записывает новую строку в «дневник» (базу данных).

________________________________________
## 8. Упрощенное объяснение
**Объяснение простыми словами:**
Представь, что `AddPlace` — это **чистая страница в твоем дневнике**.
*   Ты пишешь заголовок (`etName`) и историю (`etComment`).
*   Ты «вклеиваешь» фотографию на страницу (`ivImage`).
*   Ты можешь добавить наклейку со ссылкой на сайт или точные координаты места, где ты находишься.
*   В конце ты закрываешь дневник и убираешь его в надежное место (`HelperDB`).

**Аналогия:** Это как **создание поста** в соцсети. Ты загружаешь фото, пишешь текст и ставишь геометку. Как только ты нажимаешь «Опубликовать», всё сохраняется в памяти приложения.
