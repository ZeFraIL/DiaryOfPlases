# Описание класса: Security

________________________________________
## 1. Общая информация
*   **Имя класса:** `Security`
*   **Тип:** Логический класс / Утилита безопасности
*   **Назначение:** Это самый сложный класс в приложении. Он отвечает за защиту пароля пользователя. Он не просто сохраняет пароль в виде текста, а использует профессиональное шифрование, чтобы сделать его нечитаемым для хакеров.
*   **Взаимодействие:** Используется экраном `LogOrReg`. Взаимодействует с **Android Keystore System** (защищенное хранилище внутри телефона) и **SharedPreferences** (простое хранилище настроек).

________________________________________
## 2. Переменные (поля класса)
| Имя | Тип | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| `ANDROID_KEYSTORE` | `String` | Имя встроенного в телефон защищенного хранилища. | В конструкторе класса. |
| `ALIAS` | `String` | «Никнейм» нашего секретного ключа. | Для поиска ключа в хранилище. |
| `TRANSFORMATION` | `String` | Математическая формула для шифрования (AES). | В методах шифрования и расшифровки. |
| `keyStore` | `KeyStore` | Объект, представляющий физический сейф телефона. | По всему классу. |

*   **Keystore (Хранилище ключей):** Специальная часть аппаратного обеспечения телефона, разработанная специально для безопасного хранения криптографических ключей. Даже если кто-то украдет данные вашего телефона, он не сможет легко достать ключи из Keystore.

________________________________________
## 3. Методы класса

### Имя метода: `Security` (Конструктор)
*   **Тип:** `public`
*   **Логика:** Инициализирует соединение с внутренним сейфом телефона (`AndroidKeyStore`).

### Имя метода: `encryptAndSavePassword`
*   **Тип:** `public`
*   **Параметры:** `password` (строка), `context` (окружение).
*   **Логика:**
    1. Получает секретный ключ из сейфа (или создает его, если это первый запуск).
    2. Использует «Cipher» (цифровой шифратор), чтобы превратить пароль в бессмысленную последовательность байтов.
    3. Сохраняет эту последовательность и «стартовый код» (IV) в настройки телефона (`SharedPreferences`).
*   **Когда вызывается:** Во время регистрации пользователя.

### Имя метода: `getDecryptedPassword`
*   **Тип:** `public`
*   **Возвращаемое значение:** `String` (оригинальный пароль).
*   **Логика:**
    1. Читает зашифрованную последовательность и стартовый код из настроек.
    2. Достает секретный ключ из сейфа.
    3. С помощью ключа превращает бессмыслицу обратно в оригинальный пароль.
*   **Когда вызывается:** Во время входа пользователя в приложение.

### Имя метода: `getOrCreateSecretKey`
*   **Тип:** `private`
*   **Логика:** Проверяет, существует ли уже ключ с именем «DiaryOfPlases_PasswordAlias» в сейфе. Если нет — генерирует новый, сверхнадежный ключ стандарта AES.

________________________________________
## 4. Жизненный цикл
Этот класс существует только тогда, когда он нужен экрану `LogOrReg`. У него нет стандартного жизненного цикла Android (Activity).

________________________________________
## 5. Взаимодействие с другими компонентами
*   **Cipher:** Математический движок, который выполняет само шифрование.
*   **SharedPreferences:** Используется как «ящик» для хранения зашифрованных данных.
*   **Base64:** Инструмент для превращения набора байтов в читаемый текст, чтобы его было удобно сохранять в файл настроек.

________________________________________
## 6. Общая логика класса
Класс работает как **профессиональный слесарь-сейфовик**.
1. Он создает главный ключ и прячет его в бронированный сейф внутри телефона.
2. Он берет ваш пароль, запирает его в коробку этим ключом и отдает коробку вам.
3. Когда вам нужно снова увидеть пароль, он берет коробку, достает ключ из сейфа и открывает коробку для вас.

________________________________________
## 7. Упрощенное объяснение
**Объяснение простыми словами:**
Представь, что класс `Security` — это **машинка для создания секретных шифров**.
*   Ты даешь ей слово (пароль).
*   Она использует секретный узор (ключ), чтобы превратить это слово в абракадабру (например, «1234» превращается в «xK9!pQ»).
*   Эта абракадабра хранится в телефоне.
*   Даже если хакер найдет эту абракадабру, он не сможет угадать пароль, потому что у него нет секретного узора.
*   А секретный узор заперт в сейфе, который может открыть только это приложение.

**Аналогия:** Это как писать дневник с помощью **шифра**, который знаешь только ты и твой лучший друг. Если кто-то другой найдет дневник, он увидит только беспорядочный набор букв.
