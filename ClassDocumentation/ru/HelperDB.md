# Описание класса: HelperDB

________________________________________
## 1. Общая информация
*   **Имя класса:** `HelperDB`
*   **Тип:** Помощник базы данных (наследуется от `SQLiteOpenHelper`)
*   **Назначение:** Этот класс отвечает за создание и обслуживание локальной базы данных приложения. Он определяет структуру (таблицы и столбцы), в которой хранится вся информация о местах и контактах.
*   **Взаимодействие:** Используется различными экранами (Activity), такими как `AddPlace`, `ViewPlaces`, `AddInnerContact`, для сохранения и получения данных. Это своего рода «библиотекарь», который знает, как организованы книги (данные) на полках.

________________________________________
## 2. Переменные (поля класса)
Класс использует константы `public static final String`. Это фиксированные имена для базы данных, таблиц и столбцов, чтобы избежать опечаток в коде.

| Имя | Тип | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| `DB_NAME` | `String` | Физическое имя файла базы данных (`info.db`). | В конструкторе класса. |
| `TABLE_MY_CONTACT`| `String` | Имя таблицы для личных контактов. | В `onCreate()` и при работе с данными. |
| `TABLE_PLACE` | `String` | Имя таблицы для сохраненных мест. | В `onCreate()` и при работе с данными. |
| `PLACE_NAME` и др. | `String` | Имена конкретных столбцов (полей) в таблицах. | Для определения структуры и поиска данных. |

*   **Константы:** Использование констант гарантирует, что если мы решим изменить имя столбца, нам нужно будет сделать это только в одном месте.

________________________________________
## 3. Методы класса

### Имя метода: `HelperDB` (Конструктор)
*   **Тип:** `public`
*   **Возвращаемое значение:** отсутствует (конструктор)
*   **Параметры:**
    | Имя | Тип | Описание |
    | :--- | :--- | :--- |
    | `context` | `Context` | Контекст (окружение) приложения. |
*   **Логика:** Инициализирует помощник базы данных, указывая имя файла (`info.db`) и версию (1).
*   **Когда вызывается:** Когда какой-либо экран впервые запрашивает доступ к базе данных.

### Имя метода: `onCreate`
*   **Тип:** `public`
*   **Возвращаемое значение:** `void` (ничего не возвращает)
*   **Параметры:**
    | Имя | Тип | Описание |
    | :--- | :--- | :--- |
    | `db` | `SQLiteDatabase`| Объект базы данных для выполнения SQL-команд. |
*   **Логика:**
    1. Формирует SQL-запросы (`CREATE TABLE`) в виде строк.
    2. Выполняет эти запросы для создания двух таблиц: контактов и мест.
    3. Каждая таблица имеет свои столбцы (Название, Комментарий, GPS, Изображение и т.д.).
*   **Когда вызывается:** Только один раз, при самом первом запуске приложения или создании базы данных.
*   **Важно понимать:** Благодаря команде `IF NOT EXISTS`, таблицы не будут пересоздаваться, если они уже есть.

### Имя метода: `onUpgrade`
*   **Тип:** `public`
*   **Возвращаемое значение:** `void`
*   **Параметры:** `db`, `oldVersion`, `newVersion`.
*   **Логика:** На данный момент пустой. Предназначен для обновления структуры базы данных при выпуске новых версий приложения.
*   **Когда вызывается:** Когда номер версии базы данных в коде увеличивается.

________________________________________
## 4. Жизненный цикл
У `HelperDB` нет стандартного жизненного цикла Activity. Он следует **жизненному циклу базы данных**:
1. **Создание:** `onCreate` вызывается, если файла еще нет.
2. **Открытие:** База открывается для чтения или записи.
3. **Закрытие:** Соединение закрывается после завершения работы (обычно управляется системой или вручную в Activity).

________________________________________
## 5. Взаимодействие с другими компонентами
*   **Activity:** Используют этот класс для получения объекта базы данных.
*   **SQL:** Этот класс — основное место, где пишутся сырые SQL-команды для создания структуры данных.

________________________________________
## 6. Общая логика класса
Класс выступает в роли **архитектора** данных. Он сам не сохраняет место; он определяет, *как* это место должно быть сохранено. Он говорит: «Если хочешь сохранить место, у меня есть таблица `Places` со столбцами для имени, комментария, фото, ссылки и GPS».

________________________________________
## 7. Упрощенное объяснение
**Объяснение простыми словами:**
Представь, что `HelperDB` — это **чистый блокнот**, который идет вместе с приложением.
*   Когда ты впервые открываешь приложение, `HelperDB` расчерчивает страницы и пишет заголовки (это метод `onCreate`).
*   Он создает один раздел для «Моих контактов» и другой для «Мест, которые я посетил».
*   Каждый раз, когда ты хочешь что-то записать, ты обращаешься к этому блокноту, чтобы он показал нужные графы.

**Аналогия:** Это как **картотека**. `HelperDB` — это человек, который собрал шкаф, наклеил этикетки на ящики (таблицы) и положил внутрь папки (столбцы). Он еще не кладет туда бумаги, он просто готовит шкаф к работе.
