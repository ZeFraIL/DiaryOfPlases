# Описание класса: AddInnerContact

________________________________________
## 1. Общая информация
*   **Имя класса:** `AddInnerContact`
*   **Тип:** Активность (Activity)
*   **Назначение:** Этот экран позволяет пользователю добавить нового человека в свой приватный список «Внутренних контактов» или обновить данные уже существующего контакта.
*   **Взаимодействие:** Наследуется от `BaseActivity`. Взаимодействует с `HelperDB` для сохранения данных в базу SQLite и получает данные от `InnerContacts`, если выполняется обновление.

________________________________________
## 2. Переменные (поля класса)
| Имя | Тип | Назначение | Где используется |
| :--- | :--- | :--- | :--- |
| `etAddName` | `EditText` | Поле ввода имени контакта. | В `saveContactInBackground()`. |
| `etAddPhone` | `EditText` | Поле ввода номера телефона. | В `saveContactInBackground()`. |
| `etAddEmail` | `EditText` | Поле ввода адреса электронной почты. | В `saveContactInBackground()`. |
| `etAddComment`| `EditText` | Поле ввода дополнительных заметок. | В `saveContactInBackground()`. |
| `contactToUpdate`| `myContact` | Хранит данные существующего контакта, если мы в режиме обновления. | Проверяется в `onCreate()`. |
| `helperDB` | `HelperDB` | Помощник базы данных. | Используется для записи в таблицу. |

*   **Serializable:** Способ «упаковки» объекта `myContact`, чтобы его можно было передать через `Intent` с одного экрана на другой.

________________________________________
## 3. Методы класса

### Имя метода: `onCreate`
*   **Тип:** `protected`
*   **Логика:**
    1. Инициализирует интерфейс.
    2. Проверяет, был ли передан существующий контакт (для обновления).
    3. Если да — вызывает `populateFieldsForUpdate()` для заполнения полей.
    4. Настраивает обработчик нажатия кнопки «Save/Update».
*   **Когда вызывается:** При нажатии «Add» или «Update» в менеджере контактов.

### Имя метода: `populateFieldsForUpdate`
*   **Тип:** `private`
*   **Логика:** Берет данные из `contactToUpdate` и вставляет их в текстовые поля, чтобы пользователю не пришлось вводить всё заново. Также меняет заголовок экрана на «Update».

### Имя метода: `saveContactInBackground`
*   **Тип:** `private`
*   **Логика:**
    1. Проверяет, что все поля заполнены.
    2. Запускает фоновый поток.
    3. Если мы обновляем контакт, сначала удаляет старую запись из базы по её ID.
    4. Генерирует новый случайный ID для контакта.
    5. Использует `ContentValues` для упаковки новой информации.
    6. Записывает новую запись в таблицу `myContacts`.
    7. Закрывает базу и возвращается в основной поток, чтобы показать сообщение об успехе и закрыть экран.
*   **Что важно понимать:** Логика обновления здесь работает через удаление старой версии и вставку новой.

________________________________________
## 4. Жизненный цикл
*   **onCreate():** Настройка формы и полей.
*   **onDestroy():** Наследуется от `BaseActivity`.

________________________________________
## 5. Взаимодействие с интерфейсом (UI)
*   **EditText:** Четыре поля для имени, телефона, почты и комментария.
*   **Кнопка:** `bAdd` — меняет свой текст в зависимости от того, добавляем мы контакт или обновляем.

________________________________________
## 6. Взаимодействие с другими компонентами
*   **Intent:** Получает объект `myContact` через `EXTRA_CONTACT`.
*   **SQLite:** Записывает данные в таблицу `TABLE_MY_CONTACT` через `HelperDB`.

________________________________________
## 7. Общая логика класса
Класс работает как **обработчик формы**. Он берет ввод пользователя, организует его в понятный базе данных формат и сохраняет на постоянной основе. Он достаточно «умен», чтобы понять, создается ли абсолютно новый человек или просто исправляются данные того, кто уже есть в списке.

________________________________________
## 8. Упрощенное объяснение
**Объяснение простыми словами:**
Представь, что `AddInnerContact` — это **пустая визитка**.
*   Ты записываешь имя, телефон и почту человека на визитку.
*   Когда закончишь, ты «подшиваешь» визитку в свою личную записную книжку (`HelperDB`).
*   Если ты захочешь что-то изменить позже, приложение достает эту визитку, дает тебе стереть и написать заново, а потом подшивает её обратно.

**Аналогия:** Это как **заполнение анкеты**. Ты вводишь данные, и как только нажимаешь «Отправить», информация уходит «в архив» (базу данных) на хранение.
